# 영업이슈 뉴스

영업 현장에서 아침조회와 상담에 쓰는, 지정한 이슈에 걸린 기사만 모아 보여주는 모바일 웹 한 장.

```
collect.mjs   구글 뉴스 RSS + 네이버 검색 API → 매칭 → docs/news.json
topics.json   ★ 카테고리·검색어. 매달 손대는 파일
press.json    매체 등급표 (T1/T2). source-curator 가 후보만 올리고 편집은 사람이 한다
docs/         GitHub Pages 가 그대로 서빙
```

## 카테고리

| | 무엇을 담는가 |
|---|---|
| **간병** | 간병비·간병인·요양·치매·장기요양 |
| **수술비** | 1~5종 수술비 니즈환기 — 다빈도 수술 건수·비용 증가, 비급여 수술 증가 |
| **치료비** | **비급여 암 통합치료비** — 항암제·로봇수술·중입자·비급여 암수술의 비용. 도수치료 같은 일반 치료는 제외 |
| **실손** | 실손보험 세대교체·전환·자기부담 |
| **정책** | 관리급여·급여화·8주룰·건정심·표준약관 등 **제도** |

`must` 의 각 항목은 `|` 로 대안을 적을 수 있다 — 항목 안은 OR, 항목끼리는 AND.
「암 계열 단어 **그리고** 비용 계열 단어」 같은 2단 조건이 이걸로 표현된다.

```jsonc
"must": ["암|항암|종양", "비급여|치료비|부담"]
```

## 타사 상품 기사

자사는 노출, **타사 상품 기사는 가린다.** 단 타사에 대한 **부정적 보도**(적발·제재·분쟁·판결 등)는 노출한다.
`collect.mjs` 의 `isRivalPromo()` 가 판정한다. 기본이 차단이고 부정 어휘가 있을 때만 통과시키는 구조라,
「보장 키웠다」 「선지급」 같은 표현이 새로 나와도 새지 않는다.

⚠ 이 규칙은 CLAUDE.md §5「자사·타사 상품 비판을 자료에 담지 않는다」와 충돌하는 지점이다. 사용자 지시로 채택했다.

의존성 0개. `npm install` 없음. Node 20+ 내장 `fetch` 만 쓴다.

## 설치 (최초 1회, 약 20분)

### 1. GitHub 리포 만들기 — 3분
[github.com/new](https://github.com/new) → 이름 `sfm-news` → **Public** → Create.
Pages 무료 호스팅은 public 리포 기준이라 public 으로 만든다.
그래서 **사내 목표·실적·시상액은 이 리포에 절대 넣지 않는다.**

이 폴더를 그대로 올린다.

```bash
cd news-app
git init -b main
git add .
git commit -m "영업이슈 뉴스 초기 구축"
git remote add origin https://github.com/<아이디>/sfm-news.git
git push -u origin main
```

### 2. Pages 켜기 — 1분
리포 **Settings → Pages** → Source `Deploy from a branch` → Branch `main` / 폴더 `/docs` → Save.

몇 분 뒤 링크가 살아난다 → `https://<아이디>.github.io/sfm-news/`
**이 링크 하나만 카톡으로 뿌리면 끝이다.**

### 3. Actions 쓰기 권한 — 1분
**Settings → Actions → General → Workflow permissions** → `Read and write permissions` → Save.
(수집 결과를 봇이 커밋해야 해서 필요하다.)

### 4. 첫 실행 — 1분
**Actions 탭 → `news` → Run workflow.**
녹색이 뜨면 링크를 폰에서 열어 확인한다.

여기까지만 해도 **구글 뉴스만으로 동작한다.** 아래 5번은 선택이다.

### 5. (선택) 네이버 뉴스 붙이기 — 10분
네이버 검색 API 를 붙이면 기사마다 **요약 스니펫**과 **언론사 원문 URL**이 붙는다. 원문 URL 은 복수 카테고리 태깅에도 필요하다.

> ⚠ 네이버 검색 API 는 개발자센터에서 **NAVER API HUB(네이버클라우드)** 로 이관됐다.
> 신규 발급은 HUB 쪽이다. 도메인·헤더가 예전 글과 다르니 옛날 블로그를 따라가지 말 것.

1. [네이버클라우드 플랫폼](https://www.ncloud.com/) 가입 (본인인증 필요)
2. 콘솔 → **NAVER API HUB** → Application 등록 → **Search** 서비스 선택 → 이용 신청
3. 발급된 `Client ID` / `Client Secret` 복사
4. 리포 **Settings → Secrets and variables → Actions → New repository secret** 로 2개 등록

   | Name | Value |
   |---|---|
   | `NAVER_KEY_ID` | Client ID |
   | `NAVER_KEY` | Client Secret |

5. Actions 에서 Run workflow 재실행

무료 한도는 Search API 통합 **월 77.5만 건**. 이 앱은 1회 실행에 20건 남짓 쓰므로 한도 걱정은 없다.

구 개발자센터(`developers.naver.com`) 키를 이미 갖고 있다면 이름만 바꿔 넣으면 그대로 동작한다 —
`NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`. (구 방식은 2027-06-30 까지 유예)

## 기사 미리보기 (사진·앞부분)

카드의 사진과 미리보기 시트의 요약은 수집기가 채운다. `docs/news.json` 기사마다 세 칸이 붙는다.

| 칸 | 뜻 |
|---|---|
| `link` | 언론사 원문 주소. 구글 뉴스 중계 주소(`url`)를 풀어서 얻는다. 없으면 다음 회차에 다시 찾는다 |
| `image` | 언론사 `og:image` 주소. `''` 은 「찾아봤는데 없음」이라 다시 찾지 않는다 |
| `desc` | 언론사 `og:description` 앞 160자 |

동작 — `collect.mjs` 의 `enrich()`

1. 구글 뉴스 기사 페이지에서 서명을 읽고 `batchexecute` 로 원문 주소를 푼다. **공개 API 가 아니라 예고 없이 바뀔 수 있다**
2. 원문 HTML 을 `</head>` 까지만 받아 og 태그를 읽는다. AMP 판본이면 canonical 을 한 번 따라간다. EUC-KR 도 푼다
3. 이전 회차 값을 이월하고 **새 기사만** 찾는다. 회차당 10건 · 구글은 약 2초 간격 · 언론사는 동시 4개 · 120초 예산
   (첫 1주 설정. Actions 로그에 429 가 없으면 `enrich()` 의 `cap` 20 · `gap` 약 1초로 올린다)
4. 구글이 429(봇 확인)를 주면 **그 회차는 바로 접는다.** 우회하지 않는다. 수집 결과와 기존 데이터는 그대로 남는다

실측(2026-09-11, 국내 회선): 원문 주소 40/40 · 요약 40/40 · 사진 39/40.
같은 날 1분에 구글 요청 81건을 몰아 보내자 15분 넘게 막혔다. **GitHub 러너 IP 에서는 재 보지 못했다.**
Actions 로그의 `미리보기 대상 … · 그림 … · 실패 …` 줄로 확인한다. 사진이 계속 안 붙으면 네이버 API(원문 주소를 바로 준다)를 붙이는 게 대안이다.

사진은 **주소만 저장하고 화면이 언론사 서버에서 바로 불러온다**(`referrerpolicy="no-referrer"`). 내려받거나 다시 올리지 않는다.
사진 저작권은 언론사·통신사에 있으니 섬네일 노출 범위는 아래 「미결」과 함께 준법 확인 대상이다.

## 매달 하는 일 — 이슈 갈아끼우기

Claude Code 에서 한 마디:

```
/news-refresh 9월
```

그 달 영업방향 자료를 읽고 `topics.json` 의 이슈를 새로 뽑아 넣은 뒤,
수집을 돌려 오탐을 잡고 커밋까지 한다. (`news-topics` → 수집 → `news-qa` 순서)

손으로 고칠 때는 `topics.json` 만 건드린다.

```jsonc
{
  "id": "chiryo",                      // 영문 소문자 식별자
  "label": "치료비",                    // 화면에 뜨는 이름
  "kind": "담보",                       // 담보 | 제도
  "q": ["비급여 항암치료 비용"],          // 검색어 (구글·네이버에 그대로 던진다)
  "must": ["암|항암|종양",               // 항목끼리 AND, 항목 안 `|` 는 OR
           "비급여|치료비|부담"],
  "any": ["표적항암", "중입자"],          // 최소 1개는 있어야 통과. 많이 맞을수록 상위
  "not": ["도수치료"]                   // 하나라도 있으면 탈락
}
```

⚠ **검색어(`q`)는 관련성을 보장하지 않는다.** 수집기는 모든 검색어 결과를 한 풀에 합친 뒤
전체에 규칙을 돌린다. 「암 기사만 오겠지」 하고 `any` 에 「비용」을 넣으면 수술 진료비 통계가
통째로 들어온다. 좁히려면 반드시 `must` 를 쓴다.

`blockWords` / `blockPress` 는 **모든 토픽에 공통 적용**된다. 토픽마다 같은 제외어를 반복해 쓰지 않는다.

## 컴플라이언스

- 기사 **제목·언론사·원문 링크**만 노출한다. 본문을 재배포하지 않는다.
- **AI가 문장을 짓지 않는다.** 요약 기능은 넣지 않았다 — 상품 권유·단정 표현이 자동 생성될 여지를 구조에서 없앴다.
- 포털 재게시(다음·네이트·줌)와 매체명이 도메인으로만 나오는 곳은 원출처가 불명해서 제외한다.
- 사건사고·도박·투자권유·광고성 기사는 `blockWords` 로 뺀다.
- 가격 소구 헤드라인(「반값」·「무료」 등)은 **브리핑 상단에 올리지 않는다.** 승환 권유로 읽힌다.
- 페이지에 **회사명을 쓰지 않는다.** 공개 페이지가 공식 채널로 오인될 소지를 없앤다.
- 리포가 public 이다. **사내 수치·고객 정보는 어떤 파일에도 넣지 않는다.**

### 미결 — 사람이 판단해야 한다

- **이 페이지가 금융소비자보호법 제22조의 「광고」인가**를 준법감시인에게 확인해야 한다.
  「광고 아님」이면 CI 색과 담보명 탭을 재검토해야 하고, 「광고임」이면 심의 전까지 배포를 보류한다.
  (보험업법 제95조의4 는 2020년 삭제되어 금소법 제22조로 이관됐다.)
- **담보명 탭 + 시간순 정렬이 보험 광고 배열을 자동 생성한다.** 지금은 등급 우선 정렬로 완화했을 뿐 근본 해결은 아니다.
